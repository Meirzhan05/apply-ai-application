# Model usage

`/usage` shows the signed-in owner's model reports, including failed requests and work whose application is now cancelled. A signed-in account explicitly listed in the server-only `USAGE_OPERATOR_USER_IDS` setting can inspect another owner's view with `/usage?userId=<owner Auth UUID>`. A client role flag grants no access. The API uses verified sign-in identity, never user metadata, and responses are not cached.

The independent `model_usage_records` ledger records an invocation before calling OpenAI, then publishes its provider response identity, usage and outcome. Only server workers can access the table/RPC. Owner-state compare-and-swap callbacks do not contain provider or ledger calls. Replayed invocation reports update the original row; report reading deduplicates repeated provider response identities and prefers fuller measurements. A provider retry that returns a new response remains a separate invocation. SDK retries are disabled so hidden retries cannot silently evade attribution.

`withModelUsageContext` carries owner, application or background identity, job and run through nested model services. Existing packet workers and browser-question workers supply their durable run tokens; matching supplies the Trigger run identity. Standalone calls receive a fresh run identity. Shared service boundaries instrument packet drafting, structured resume generation and grounding, essay generation and grounding, matching, and browser field mapping. Later autonomous callers inherit the same accounting without a separate provider path.

The ledger records no prompt text, résumé facts, generated answers, raw errors, secrets or provider connection URLs. An interrupted request leaves a started record with unknown measurements. A failed/aborted request retains an unmeasured record. Usage returned before a later grounding failure or application cancellation remains in the ledger. Failed final persistence leaves the initial unknown record and fails the service call; it does not pretend no cost occurred.

The rate snapshot is `openai-standard-2026-10-01`, sourced from [official OpenAI pricing](https://developers.openai.com/api/docs/pricing), with model, input-context band and rates retained on each record. Estimates use a reported default service tier and complete input/cached/cache-write/output measurements. Unknown models, tiers or missing token components produce unknown cost. Cached and cache-write tokens are subsets of total input. Output already includes reasoning, so reasoning detail is never added again. See [OpenAI reasoning documentation](https://developers.openai.com/api/docs/guides/reasoning).

The known estimate is a subtotal, not a complete bill. Projected scheduling reservations are shown separately. Browser costs and other service overhead are outside this model ledger. Reconciled invoice charges remain unavailable until the later service-cost implementation. Older applications have no retrospective measured usage; records are not invented from reservations.

Local demo mode uses a separate private `.data/model-usage.json`. Vitest uses a process-isolated temporary ledger; tests do not contact OpenAI or production services. Production requires the usage migration before web/worker rollout. The migration explicitly grants service-role access and revokes frontend roles, because new Supabase tables are no longer guaranteed to receive automatic Data API grants.

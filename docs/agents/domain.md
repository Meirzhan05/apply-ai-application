# Domain Docs

This repository uses one domain context: a root `GLOSSARY.md` and `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` when present and the ADRs in `docs/adr/` relevant to the work. If they do not exist, proceed with the terminology used by the code and existing product documents. Domain-modeling work creates these documents when terms or decisions need to be recorded.

## Vocabulary

Use glossary terms in issue titles, specifications, reviews, and tests. If a needed term is absent, first check the existing project terminology; record a genuine terminology gap for domain-modeling work.

## Architectural decisions

Read relevant ADRs before proposing a conflicting implementation. Identify the ADR and explain why the decision should be reopened rather than silently changing it.

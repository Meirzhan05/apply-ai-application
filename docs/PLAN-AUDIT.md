## Contract compatibility

`ApplicationPacket.schemaVersion` identifies the wire format. `ApplicationPacket.version` counts document revisions and can be 2 or higher. New drafts and answer/cover-letter revisions carry `schemaVersion: 1` and file manifests. Both new approvals carry `version: 1`.

The original persisted formats had no explicit schema marker or approval version. Missing markers retain their original v1 semantics; reading a record never adds fields that would change its approved hash. An intentional revision generates the current manifest and clears consent. Unknown explicit schema or approval versions are rejected. Legacy packets without manifests retain their previous file semantics until revised; they do not provide the new byte-binding guarantee retroactively.

Generated PDFs are reproduced from owner-scoped packet/profile content rather than stored as public objects. The preview and upload each verify their generated bytes against the hash approved in the packet. Uploaded original resumes and captured review/confirmation images remain in private Supabase Storage. No public resume endpoint exists.
